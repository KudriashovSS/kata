# База знаний о проекте

На вход формальное описание требуемого проекта, ограничения, формат результата.  На выходе структурированная и связанная документация: требования, ADR, use cases, design docs, specs (HTTP, event operations), БД связанных сущностей полученных в результате системного анализа.

* разработка с ограничениями (чтобы итерации были короткими): задается количество операций, use cases.
* ревью человеком и агентами.
* хранение в xmemory. свои разработки вокруг того: как выглядит схема структурированных требований к Системе, получение фактов для хранения (может ли это xmemory?).

Проверки (evaluations):

* генерация документации без памяти и с памятью. проверка конечного результата (количество полученных документов, качество, полнота).
* внесение изменений в проект, с памятью и без (качество, полнота изменений).

## Требования к проекту

### Обрабатывать поток задач из выбранного источника

* в рамках проекта просто требования от человека переданные агенту через чат

### Цикл «выполнил → оценил → извлёк урок»

* разработка артефактов,
* оценка агентами,
* оценка людьми,
* обратная связь,
* анализ рута,
* вычленение факта на изменение,
* помещение в очередь на проверку
  * проверка что такой факт уже проверяется, тогда ожидание и перегенерация
  * если факта нет, то запуск перегенерации с новым фактом (факт должен быть изолирован от остальной системы)
  * оценка что проблемы больше нет и не появилось новых, если нет, то повторение или блокировка по какому либо признаку.
  * внесение факта в общедоступный БЗ

### Память переживает рестарты

* используем xmemory для стуктурированного храненеия данных о системном анализе

### Обучиться на своих данных до финала, показать дельту чистая/обученная

* Возможно есть проблема с разделением БД системного анализа (процесса) и БД готовых фактов проекта. По идее это разные знания.
* Берем начальные требования и просим сгенерить агента с памятью о системном анализе и без. Сверяем проработку требований.
* Берем готовый провект и вносим различные изменения: расширения требований, изменение требований, конфликтующие требования. Используем агента без памяти и с памятью структурированной о проекте + память о системном анализе.
