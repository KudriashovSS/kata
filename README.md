# kata — системный дизайн как память агента

Хакатон агентской памяти. Гипотеза, которую проверяем:

> **Память технических фактов о системном дизайне проекта (в xmemory) улучшает работу
> кодового агента** — меньше токенов и переделок, меньше архитектурных ошибок.

Инвертируем задачу системного анализа: не проектируем схему знаний заранее и не предсказываем
будущее — агент **реверс-инжинирит технические факты из уже существующего кода**, человек только
выбирает нужные срезы и ревьюит сомнительное. Дальше эта память живёт рядом с проектом,
актуализируется при каждой задаче и (гипотеза) делает будущие реализации качественнее и дешевле.

Наша работа = **хороший скилл + честные эвалы**. Всё остальное делает фронтир-модель на вайбе.

## Happy path

1. Пользователь вызывает скилл `/tech-facts`.
2. Агент разведывает репозиторий и поднимает **локальный UI** (`localhost:4747`): лендинг-picker
   со срезами системного дизайна, которые реально есть в этом проекте.
3. Пользователь отмечает нужные срезы прямо на странице — решение уезжает агенту само
   (блокирующий `await`, без копипасты JSON в чат).
4. Агент извлекает срезы параллельно, пишет факты в **xmemory** (схему проектирует сам под
   выбранные срезы), уверенное подтверждает сам, сомнительное отдаёт человеку на ревью.
5. Дальше агенту дают поток задач: перед задачей он **читает** релевантные факты, после —
   **дополняет и актуализирует** память (через хуки).
6. Между задачами (или по cron) — фаза **самоулучшения**: отдельная сессия дедуплицирует факты,
   правит схему, помечает устаревшее.
7. Эвал сравнивает прогоны: без памяти / с памятью / с памятью и самоулучшением.

## Как это закрывает требования хакатона

- **Поток задач** — реальные задачи разработки в целевом репозитории (и реплей его истории в эвалах).
- **Цикл «выполнил → оценил → извлёк урок»** — задача выполнена → реальность кода сверена с
  памятью → расхождения становятся candidate-фактами / пометками stale.
- **Уроки меняют поведение** — следующий агент читает обновлённые active-факты перед задачей.
- **Память переживает рестарты** — внешнее хранилище (xmemory / файлы), каждый запуск агента —
  новый процесс.
- **Дельта чистая/обученная** — измеряется прогонами memory-off / memory-on: [evals/README.md](evals/README.md).
- **Устаревание, противоречия, HITL, observability** — жизненный цикл факта
  (candidate → active → stale), авто-подтверждение с отзывом, журналы MemoryRead/MemoryWrite.

## Полевой тест скилла

Скилл прогнан на реальном рабочем репозитории (services-platform, contract-first .NET): извлечено
37 фактов по 4 срезам, все прошли ревью; вторая итерация перенесла память в живой xmemory-инстанс
(цепочка «факт → ревью → задача» достаётся обходом графа, агентская выборка работает). 23 доработки
каталога и протокола по итогам внесены. Третья итерация — UI: один порт, авто-подтверждение,
конструктор сайта, обратная связь без копипасты.

## Глоссарий

- **тип факта** — описание элемента системного дизайна (внешние интеграции, зависимости модулей).
- **факт** — собираемая единица: «сервис А ходит в сервис Б», «модуль С зависит от модуля Д».
- **срез** — набор типов фактов, который человек выбирает в picker'е.
