# Прототип: база технических фактов о проекте

Инвертируем задачу системного анализа: не проектируем схему знаний заранее и не предсказываем
будущее — агент **реверс-инжинирит технические факты из уже существующего кода**, человек только
выбирает нужные срезы и подтверждает результат. Дальше эта память живёт рядом с проектом,
актуализируется при каждой задаче и (гипотеза) делает будущие реализации качественнее и дешевле.

Наша работа = **хороший скилл + честные эвалы**. Всё остальное делает фронтир-модель на вайбе.

## Как это выглядит для пользователя

1. Ставит скилл `tech-facts` и говорит агенту: «построй базу технических фактов о проекте».
2. Агент разведывает репозиторий и поднимает локальный **picker** (см. [references/picker.html](skills/tech-facts/references/picker.html)) —
   красивую страницу со срезами, которые реально есть в этом проекте: event graph, модульные
   зависимости, владение данными, контракты, инварианты, грабли…
3. Пользователь отмечает нужное. Можно выбрать один срез («мне достаточно Event graph») —
   пользователя в тиски не зажимаем. В тиски зажимается агент: всё, что он извлёк, обязано лечь
   в реляционную схему с evidence.
4. Агент извлекает факты, показывает **человекопонятные диаграммы** (а не сырой UML) на ревью.
5. После подтверждения — сохраняет в память: xmemory (агент сам придумывает схему под выбранные
   срезы) или файловый fallback. Схема расширяемая: захотели больше срезов — доизвлекли, схема
   доросла.
6. В будущей разработке любой агент перед задачей читает релевантные факты, после задачи —
   актуализирует их. Каждое чтение и запись логируются: видно, какой факт в какую задачу попал.

## Как это закрывает требования хакатона

- **Поток задач** — реальные задачи разработки в целевом репозитории (и реплей его истории в эвалах).
- **Цикл «выполнил → оценил → извлёк урок»** — задача выполнена → реальность кода сверена с памятью →
  расхождения становятся новыми candidate-фактами / пометками stale.
- **Уроки меняют поведение** — следующий агент читает обновлённые active-факты перед задачей.
- **Память переживает рестарты** — внешнее хранилище (xmemory / файлы в репо), каждый запуск агента —
  новый процесс.
- **Дельта чистая/обученная** — измеряется реплеем истории: [evals/README.md](evals/README.md).
- **Устаревание, противоречия, HITL, observability** — встроены в жизненный цикл факта
  (candidate → active → stale) и журналы MemoryRead/MemoryWrite, см. протокол памяти.

## Что попробовать дальше

1. Прогнать скилл на живом репозитории (Throne / форк multica / рабочий сервис) — построить память
   по одному срезу (event graph) и посмотреть качество извлечения.
2. Собрать первый эвал: выбрать реперный коммит, одну «фичу из будущего», написать к ней 5–10
   архитектурных проверок.
3. Подключить xmemory-адаптер, когда будет доступ к инстансу (до этого работает файловый).
