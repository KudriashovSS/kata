## Контракт раннера

- На вход: список задач + режим памяти (`memory-off` / `memory-on`; `memory-on+evolve` — этап 2).
- Каждая задача — **отдельная сессия** агента, изоляция состояния между задачами.
- Работа с памятью — **по хукам**: на старте сессии агент читает релевантные факты из xmemory,
  на завершении дополняет/актуализирует их. Разница между режимами — только наличие хуков,
  промпт/модель/инструменты идентичны.
- На выход: артефакты прогона (дифф, логи, что уехало в контекст, какие мутации ушли, токены,
  время), которые подхватывает каркас [`../harness/`](../harness/). Трассировку пишет **раннер**,
  а не память: так прогон без памяти логируется тем же кодом и прогоны сравнимы.

## Механика хуков: что можно и чего нельзя

| Хук | Что умеет | Наша роль |
| --- | --- | --- |
| **SessionStart** | stdout хука **инжектится в контекст**; таймаут по умолчанию 600 с | **чтение памяти**, готовой командой: `xmemcli context --text --timeout N` отдаёт стартовый пакет по инстансам, привязанным `binding add <id> --tier autoload`. Свой запрос писать не нужно |
| **UserPromptSubmit** | тоже добавляет контекст, умеет блокировать; таймаут 30 с | запасной вариант, если факты нужны под конкретный промпт, а не на сессию |
| **Stop** | срабатывает, когда агент закончил отвечать, **умеет вернуть его в работу** (exit 2) | **запись памяти**: хук не пишет сам, а заставляет агента сделать шаг актуализации. Нужен гард от петли — иначе бесконечный цикл |
| **SessionEnd** | **вывод игнорируется**, все SessionEnd-хуки делят **1.5 с** (поднимается максимум до 60 с) | **не использовать для записи.** Только уборка и логирование |

Из этого следует: «на старте прочитал, на завершении записал» одним хуком **не собирается** —
разбор «что изменилось» требует модели, а в SessionEnd нет ни вывода, ни времени. Запись всегда
идёт шагом самого агента; хук только гарантирует, что этот шаг случится.

Всё, что можно измерить, логирует раннер. В самой памяти агент оставляет только доменную связь
«задача ↔ факты» (объект `Task`) — её раннер знать не может, а демо и attribution держатся на ней.

Что именно агент делает на каждом шаге — в
[`../skills/tech-facts/usage-contract.md`](../skills/tech-facts/usage-contract.md). Он же кладётся
в standing instructions инстанса: `xmemcli instance instructions <id> "<текст>"` — тогда контракт
едет вместе с памятью, а не только через хук.

## Предлагаемая раскладка

```
dataset/
  repo.md              целевой репозиторий и реперный коммит
  tasks/               задачи: одна задача — один файл (формулировка + скрытые проверки)
  facts/               стартовые типы фактов / срезы для xmemory
  runner/              скрипт прогона задач
  hooks/               SessionStart (чтение) и Stop (шаг записи) — включаются в memory-on
```
