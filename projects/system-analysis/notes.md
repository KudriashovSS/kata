# Заметки по проекту Системного анализа

## Цель проекта

Агенты без структурированной памяти уже могут справлятся с задачами указанными в проекте используя статический контекст проекта (спеки, код и тп). Цель проекта - не добавить абсолютно новых функционал, а оптимизировать и улучшить работу знаниями о проекте через их структурированное хранение. Отделить представление (документы проекта) от данных (реальные факты). Уменьшить деградацию знаний о проекте по мере роста фактов и нарастания изменений.

## Функционал

* использование xmemory для структурированного хранения фактов о разрабатываемой Системе полученных в результате Системного анализа. Для каждого факта разрабатывается своя схема с атрибутами, факты связаны между собой.
  * цели
  * не цели
  * глоссарий
  * бизнес требования
  * нефункциональные требования
  * роли
  * сценарии
  * эпики
  * истории
  * бизнес сущности
  * аттрибуты бизнес сущностей
  * связи между фактами
* xmemory xранит факты о PRD, АДР, Use Case, спецификациях на разработку.
* формирование фактов проекта с помощью LLM из входящих источников
  * готовые спеки
  * обсуждения команды
  * обсуждение с заказчиком
* запись xmemory новых или измененных фактов, деактивация неактуальных.
* чтение агентом из xmemory фактов о проекте при формировании документации, ответов на вопросы по Системе
* проверка конфликтующих, дублирующих фактов между собой
* добавление к фактам атрибутов. как пример у разных сущностей могут быть:
  * даты внесения
  * автора
  * актуальности
  * чем заменена
* факты на каждом уровне абстракции должны быть не протеворечивы, то есть факты требования не могут нарушать факты цели или существовать без верхнеуровневых требований.
* для каждого факта должна хранится информация откуда он был получен (название мероприятия, название документа, ссылка на статью и тп)

## Фазы

### MVP 0. хранение фактов о PRD

* генерация и разбор только PRD
* поддержка фактов только о бизнес требованиях
* вычленение фактов из других внешних источников
* поддержка проверки дублей, конфликтов, замены фактов.
* mcp или утилита с gates для проверки корректности структуры и связей добавляемых фактов

## Структура xmemory хранения фактов

Общие атрибуты
  * автор
  * дата добавления
  * активность
  * откуда получена
  * кто добавил

* цель
  * текст
  * уникальный идентификатор (например, G 1)
* бизнес требование
  * текст
  * уникальный идентификатор (например FR 1)
  * ссылается на "цель", может ссылаться на несколько "целей".
  * ссылки или перечисление "глосарий идентификаторов" (подумать над типом?)
* роль
  * название
  * ссылается на "бизнес требование"
  * уникальный идентификатор (например ROLE 1)
* нефункциональное требование
  * текст
  * уникальный идентификатор (например NFR 1)
  * ссылается на "цель", может ссылаться на несколько "целей".
* бизнес сущность
  * название
  * описание
  * версия
  * ссылка на "бизнес требование", где появился
* атрибут бизнез сущности
  * название
  * описание
  * тип
  * ограничения
  * версия
  * ссылка на "бизнес сущность"
  * ссылка на "бизнес требование"
* глосарий
  * название
  * описание
  * связь с другими сущностями глосария

## Поддерживаемые сценарии проекта

### Агент анализирует документы проекта и наполняет xmemory фактами о проекте

### Агент добавляет в xmemory новый факт о проекте

### Агент добавляет в xmemory новую версию факта о проекте, если об этом сказано пользователем или понятно из контекста (например, новая версия требований)

### Агент недобавляет в xmemory факт который уже есть в проекте

### Агент недобавляет в xmemory факт который конфликтует с верхнеуровневыми фактами

### Агент недобавляет в xmemory факт который конфликтует с фактами на этом уровне

### Агент деактивирует факт, который больше неактуальный

### Агент генерирует документы проекта на основании текущих фактов

### Аналитик запрашивает произвольную информацию о проекте и агент ответчает опираясь на факты

## Валидации работы (evaluations)

* агент должен наполнить ожидаемыми фактами xmemory после анализа текста
* агент должен сгенерить ожидаемый текст по фактам и шаблону
* агент должен сгенерить одинаковый текст после разбора на факты и генерации документа обратно
* агент не должен добавлять факты противоречащие верхнеуровневым фактам

## Тестирование проекта в хакатоне

Измеряется эффективность внесения изменений: соблюдение шаблона документа, переписывание фактов в документе, поиск противоречий запрятанных в разных документах.

* есть репозиторий с текстовыми документами проекта. агент с памятью и без вносят изменения в документацию
  * добавляют новые требования.
  * добавляют конфликтные требования.
  * удаляют требования
* агент без памяти может пользоваться только анализом текста документов и анализировать историчность через git log, то есть обычные инструменты.
